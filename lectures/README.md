## Deck conventions

Every `slides.md` in this directory follows the same rules — the decks link here
(`#deck-conventions`) rather than repeating them:

1. **One idea per slide**, ≤ 6 bullet lines, no paragraph walls; tables only where a
   table is the content.
2. **Speaker notes are separated from student-facing content**: each slide carries a
   `> Notes —` blockquote directly beneath it (delivery guidance, answers, timing
   cues) that prints/stays behind when slides are exported without notes.
3. **Diagrams**: Mermaid (`flowchart`, `sequenceDiagram`, `stateDiagram-v2`) or
   labeled ASCII; every edge/row is labeled; all diagrams are original to this
   repository — no copyrighted figures are reproduced, and no screenshots are faked
   (reconstructed UI text is labeled as such).
4. **Deck outline**: every deck opens with a two-column slide-number/title table so
   instructors can navigate and trim.
5. **Every deck closes with**: a summary slide, an exit-question slide (feeding the
   matching weekly quiz pool), and a demonstration-instructions block for the
   instructor (with ITI items and offline fallbacks flagged).
6. **Numbers in decks are either machine-checked or flagged**: worked examples that
   mirror [assessment](../assessments/README.md) items carry the same verified values;
   illustrative/rule-of-thumb figures are marked ⚠ verify in the speaker notes.

## Instructor notes

- All ⚠ items (lab-image verification, edition-specific readings, provider
  documentation, enrollment-dependent timings) are flagged in-place and
  collected per-lecture in each `notes.md` prep checklist.
- Timing plans deliberately vary (workshops, clinics, and the defense lecture
  differ from expository lectures) — the template's element checklist still
  applies to every package.
